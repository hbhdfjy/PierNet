# 自动训练平台专利大纲

版本日期：2026-05-11

本文档是面向专利撰写的技术大纲，用于后续扩展为正式的说明书、权利要求书、摘要和附图说明。当前重点是固定可保护的技术方案边界，而不是撰写最终法律文本。

## 1. 拟定名称

一种面向科学仿真语言路由器的自动化训练调度、监控与权重管理方法、系统、设备及存储介质。

可选名称：

- 一种面向 Token Router 的数据感知型自动训练平台及方法。
- 一种结合 GPU 锁定、缓存构建和断点恢复的科学语言路由模型训练系统。

## 2. 技术领域

本发明涉及机器学习训练平台、科学仿真数据处理、GPU 资源调度、模型训练过程管理、检查点管理和前后端协同监控，尤其涉及针对科学仿真语言路由器的单卡自动训练与可恢复管理方法及系统。

## 3. 背景问题

Token Router 训练依赖由科学语言样本构建出的路由数据，同时还依赖嵌入模型、tokenizer、场景选择、训练/测试切分、GPU 状态和检查点文件。传统手工训练方式通常存在以下问题：

- 训练数据、场景选择、嵌入模型和缓存目录不一致时容易产生不可复现实验。
- 多个训练任务可能误用同一 GPU，导致显存冲突或训练中断。
- 长时间训练中断后，平台难以判断任务是运行、停止、完成、异常终止还是等待保存。
- 检查点数量增长快，占用磁盘空间，且恢复训练时缺少兼容性校验。
- 前端日志、曲线、GPU 状态和任务状态若由不同来源刷新，容易出现状态漂移。

## 4. 核心技术方案

该方案将 Token Router 训练封装为一个数据感知、资源感知和状态可恢复的自动训练闭环：

1. 训练数据发现：从路由数据 manifest、便携式 Parquet 分区或兼容 JSONL 文件中聚合可训练仿真器、场景、样本数和文件大小。
2. 训练参数配置：前端选择仿真器、子场景、GPU、批大小、测试比例、评估间隔、学习率、权重衰减、保留权重数量和恢复训练来源。
3. GPU 可用性判定：后端读取 `nvidia-smi` 的显存和利用率，并结合平台内活跃任务对 GPU 进行逻辑锁定。
4. 预处理缓存构建：根据仿真器、场景集合、测试比例、输入表示、嵌入模型和 tokenizer 生成确定性缓存名，构建或复用训练缓存。
5. 训练进程启动：后端创建独立训练子进程，设置 `CUDA_VISIBLE_DEVICES`、停止令牌、运行目录、日志路径和训练命令。
6. 过程监控：平台从进程状态、训练日志、指标 JSONL、测试指标、检查点目录和停止状态文件综合推断任务状态。
7. 权重管理：训练过程中按 epoch 保存检查点，按用户配置保留最近 N 个 epoch，同时维护 latest/final 权重和兼容性元数据。
8. 安全停止与恢复：停止请求写入带 token 的控制文件并发送信号，训练脚本在安全点保存检查点；恢复训练前校验 checkpoint 与当前训练配置兼容。

## 5. 主要模块

### 5.1 数据集聚合模块

- 扫描 Token Router 数据目录、manifest 和便携式分区。
- 汇总仿真器、场景、样本数、文件大小、输入表示和嵌入元数据。
- 向前端提供可选择的数据集列表，并拒绝不存在或不完整的场景组合。

### 5.2 GPU 资源判定与锁定模块

- 读取 GPU 型号、显存占用、利用率和进程占用情况。
- 基于显存阈值、利用率阈值和平台活跃任务判断 GPU 是否可用。
- 训练任务创建时在锁内二次校验 GPU 状态，避免并发提交抢占同一 GPU。

### 5.3 训练缓存与输入表示模块

- 解析路由数据中的聊天模板、嵌入模型、tokenizer 和输入表示。
- 检查本地 embedding backbone 是否可解析。
- 根据数据选择和模型元数据生成确定性 prepared cache 名称。
- 对路由样本进行切分、嵌入或 token 缓存，并保存训练/测试摘要。

### 5.4 训练执行模块

- 以独立进程运行 Token Router 训练脚本。
- 设置随机种子、设备、AMP、DataLoader、长度分桶采样和评估间隔。
- 输出训练日志、训练指标、测试指标、分场景指标和 checkpoint 文件。

### 5.5 状态恢复与监控模块

- 从持久化任务表恢复历史任务。
- 结合 PID 是否存活、日志尾部、训练指标文件、停止状态文件和最终权重判断任务状态。
- 为前端提供任务列表、任务详情、训练曲线、日志和最近检查点。

### 5.6 检查点与恢复训练模块

- 每个 epoch 保存 `router_epoch_*.pt`，并根据 `keep_last_epochs` 删除更早 epoch 权重。
- 维护 `router_latest.pt`、`router_final.pt` 和检查点元数据。
- 删除检查点前确认任务不在运行，并限制删除路径位于训练 run 目录内。
- 恢复训练前比较仿真器、场景、输入表示、嵌入模型、tokenizer 和 prepared summary 等兼容性信息。

### 5.7 前端训练工作台模块

- 提供训练总览、GPU 状态、数据集选择、新建训练、任务管理、详情页、曲线、日志和训练文件管理。
- 通过统一 API 周期性刷新数据集、GPU、任务、日志、曲线和检查点。
- 将任务状态、停止提示、权重保留策略和文件删除保护同步到界面。

## 6. 关键创新点

- 将路由数据 manifest、嵌入 backbone、训练缓存、GPU 锁和训练子进程绑定为一个可校验的启动契约。
- 使用确定性缓存命名机制，使相同数据选择和输入表示复用同一 prepared dataset，减少重复预处理。
- 通过操作系统进程、平台持久化状态、训练日志、指标文件和 checkpoint 文件多源融合恢复任务状态。
- 使用带令牌的停止控制文件实现平台授权停止，并在训练安全点保存权重，降低强制中断导致的模型损坏风险。
- 将 checkpoint 保留数量作为训练配置，由平台自动清理旧权重，兼顾恢复能力和磁盘占用。
- 在恢复训练前执行配置兼容性检查，避免使用不匹配数据或嵌入模型继续训练。

## 7. 技术效果

- 降低训练启动和恢复的人为配置错误，提高实验可复现性。
- 避免多个任务误占同一 GPU，提高远程服务器资源利用的可控性。
- 在服务重启、浏览器关闭或任务异常结束后仍能查看任务历史、日志和最终状态。
- 自动控制 checkpoint 数量，减少磁盘压力。
- 让前端展示的训练状态、进度、日志、曲线和权重文件与后端运行状态保持一致。

## 8. 权利要求布局建议

1. 独立方法权利要求：覆盖数据集发现、GPU 判定、缓存构建、训练启动、状态监控、检查点管理和安全停止恢复的完整训练流程。
2. 独立系统权利要求：覆盖数据集模块、GPU 模块、缓存模块、训练执行模块、状态恢复模块、检查点模块和前端监控模块。
3. 设备权利要求：覆盖执行上述训练调度方法的服务器或计算设备。
4. 存储介质权利要求：覆盖保存程序指令后执行上述方法的非暂态计算机可读存储介质。
5. 从属权利要求：分别保护 GPU 二次校验、prepared cache 哈希、checkpoint 兼容性校验、状态多源推断、令牌化停止文件和最近 N 个 epoch 权重保留策略。
