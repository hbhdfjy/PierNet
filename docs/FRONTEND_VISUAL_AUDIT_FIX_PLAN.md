# 前端真实截图审查与修复计划

更新时间：2026-05-16

## 审查原则

本轮不再只依赖 Playwright 的 DOM 溢出指标，也不只看拼图。审查以真实页面 PNG 截图为准，覆盖桌面、类 Chrome 桌面、移动端和极窄屏，并分别检查日间与夜间主题。

截图来源：

- 远程截图目录：`/tmp/piern-ui-real-audit-final2`
- 本机审查目录：`/private/tmp/piern-ui-visual-audit/final2`
- 截图规模：20 个页面 × 4 个视口 × 2 个主题 = 160 张 PNG

## 已确认原因

Playwright 与本机 Chrome 的审查差异主要来自以下几点：

1. Playwright 使用服务器 bundled Chromium，本机 Chrome 的字体渲染、缩放、默认字体和抗锯齿可能不同。
2. 之前主要看 DOM 的 `scrollWidth/clientWidth`，能发现溢出，但发现不了低对比、视觉拥挤、半截导航项、浅色主题不协调等审美问题。
3. contact sheet 会缩小页面，容易漏掉小组件低对比、细小裁剪、按钮密度和局部遮挡。
4. 横向滚动导航、表格、列表等“可滚动但不美观”的问题不一定会被 DOM 规则判定为 bug。

## 已确认 Bug

### 1. 浅色主题彩色 Badge 对比度不足

影响范围：

- `MODFLOW（地下水）`
- `SimPEG（地球物理）`
- `gcam`
- `English / 中文 / 专业技术 / 简洁`
- 阶段标签，例如 `阶段 2`、`阶段 3`、`阶段 4`

表现：

- 浅色主题下沿用了暗色主题的 `text-*-300/400`，文字发虚。
- 用户截图中 `MODFLOW（地下水）`、`SimPEG（地球物理）` 低对比明显。

修复方向：

- 为 `[data-theme=light]` 单独覆盖彩色 badge 文本、边框和背景。
- 浅色主题采用更深文字色、更稳定浅底色，避免只靠透明 Tailwind 色阶。

验收标准：

- 浅色主题下彩色 badge 在桌面、移动、窄屏均清晰可读。
- 不再出现浅底浅字。

状态：已初步修复；继续保留为复查项。

### 2. 移动端平台导航会露出半截文字或半截导航项

影响范围：

- 数据合成平台顶部二级导航
- 自动训练平台顶部二级导航
- 主要出现在 `320px` 窄屏和横向滚动导航区域

表现：

- 当前路由对应导航项之前，左侧可能露出半个上一个导航项文字。
- 用户截图中顶部区域看起来像组件被切掉。
- 自动滚动到 active item 后有所改善，但仍有半截相邻项，视觉不够干净。

修复方向：

- 移动端导航改为真正的横向工具条，不显示分组标题。
- 当前路由进入时将 active item 滚到可见区域起始位置。
- 如果仍有半截项，需要考虑改成“当前组下拉 + 当前项列表”或两行分段控制。

验收标准：

- 320px 宽度下不出现半截中文或半截控件。
- 当前页面入口明确可见。
- 横向滚动保留，但不影响首屏可读性。

状态：部分修复。仍需去掉移动端孤立的 `>` 分隔符，并让当前项靠左后不露出无意义碎片。
